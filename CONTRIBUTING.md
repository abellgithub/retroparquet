# Contributing to Retroparquet

Thank you for your interest in contributing to the Retroparquet file format specification!

## How to Contribute

### Reporting Issues

If you find an error, ambiguity, or area for improvement in the specification:

1. Check if a similar issue already exists
2. Open a new issue with a clear description
3. Include the section of the specification that needs attention
4. Provide suggestions for improvement if possible

### Proposing Changes

To propose changes to the specification:

1. Fork the repository
2. Create a new branch for your changes
3. Make your changes to the specification document
4. Ensure your changes are clear and well-documented
5. Submit a pull request with a detailed description

### Specification Changes

When proposing changes to the specification:

- **Clarity**: Ensure explanations are clear and unambiguous
- **Completeness**: Cover all necessary details for implementation
- **Compatibility**: Consider backwards compatibility when proposing changes
- **Examples**: Include examples where helpful
- **Consistency**: Maintain consistency with existing style and terminology

### Documentation Style

- Use clear, technical language
- Include code examples and diagrams where appropriate
- Follow the existing structure and formatting
- Update the version number if making substantial changes

## Code of Conduct

- Be respectful and constructive
- Focus on technical merits
- Welcome newcomers and help them contribute
- Assume good intentions

## Questions?

If you have questions about contributing, feel free to open an issue for discussion.

Thank you for helping improve the Retroparquet specification!
